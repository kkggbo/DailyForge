# DailyForge 循环模板编辑页优化改造方案

> 版本：v0.2
> 日期：2026-08-23
> 状态：**已确认，进入实施**（2026-08-23 用户确认以下决策）
> 适用范围：`/cycle-templates/:templateId/edit` 编辑页
> 读者：主控会话 / 前端架构师 / 后端应用服务构建师 / 产品需求确认

---

## 0. 背景与目标

用户反馈编辑页两大问题：

1. **页面过长 + 滚动卡顿**：每个动作卡片默认渲染完整内容（动作备注 + 每组执行项 + 每个指标输入框），模板动作多时页面极长、滚动掉帧。
2. **“时长”单位不区分场景**：当前只有 `duration_seconds`（秒）。短项目（如休息、平板支撑）用秒合理，但长项目（如跑步、椭圆机、骑行）填“30 分钟”需要换算成 1800 秒，不符合直觉。

本次改造目标：

- 动作卡片**默认折叠**，只显示 序号 + 名称；点击展开按钮再显示 备注 / 标签 / 执行项。
- 时长单位**拆分为 秒 / 分钟**，长项目直接用分钟填写。
- 顺带排查并纳入其他低风险优化点。

## 1. 现状梳理（已核实代码）

编辑页组件链：

```
CycleTemplateEditPage
└─ CycleTemplateEditor（天导航 + 每日动作列表）
   └─ ExerciseStructureEditor（动作卡片）
      └─ ExerciseItemEditor（执行项卡片）
         └─ MetricEditor（指标行）
```

关键现状：

- 动作卡片头部已显示 `动作 N` + 名称 + 结构类型/肌群/器械标签 + 操作按钮（更换/上移/下移/删除）。
- 卡片体（备注 + 执行项 + 指标输入框）**无条件全部渲染**，是页面长度的主要来源。
- 已有 `isNoteExpanded` 备注折叠模式（有备注则自动展开），可复用该交互范式。
- 指标键是**封闭字典**：
  - 前端联合类型：`cycle-template/types/cycle-template.ts`、`workout/types/workout.ts`
  - 前端展示配置：`cycle-template/lib/cycle-template-metric-config.ts`（label/unit/step/min/max/适用结构）
  - 后端枚举：`plan/domain/model/MetricKey.java`（value + unit）
  - 打卡页指标名：`workout/lib/workout.ts` 的 `metricLabels`
- 指标单位**不落库**：响应体 `metricUnit` 由后端枚举 `getUnit()` 推导（英文，如 `seconds`）；请求体不传单位。
- 后端校验是枚举驱动：`ExerciseStructurePolicyService` 用 `MetricKey.fromValue()` 判定合法键，**加枚举值即自动放行**；`metric_key` 列为 `VARCHAR(64)` + 唯一键，**无 CHECK 约束** → **加新键不需要数据库迁移**。
- 动作元数据（肌群/器械）已按缺失 ID 批量拉取并缓存（`exerciseMetaById`），无 N+1 问题。

## 2. 方案 A：动作卡片默认折叠（纯前端）

### 2.1 交互设计

- **常显头部**：`动作 N` + 名称 + 结构类型标签 + 操作按钮（更换/上移/下移/删除）+ **展开/收起按钮**。
- **默认折叠**：隐藏 动作备注、肌群/器械标签、执行项列表、“新增一组”按钮。
- **展开态**：显示全部详情；再次点击收起。
- **折叠态错误可见性**：若该动作存在字段错误（`fieldErrors` 中前缀 `day.{dayIndex}.exercise.{exerciseIndex}.` 的键非空），折叠态显示错误角标（如“有 2 项待修正”），展开后显示详细错误。
- **锁定（locked）态**：仍可展开/收起，仅查看。
- **备注交互收敛**：现有“添加备注/收起备注”逻辑并入折叠区域，不再单独展开。

### 2.2 技术实现

- `ExerciseStructureEditor.tsx`：
  - 新增 `isExpanded` state（默认 `false`）。
  - 将 备注区、`FieldError` 区、执行项列表、新增一组按钮整体包进 `isExpanded ? <>…</> : null`。
  - 用 `errorPrefix` 前缀扫描 `fieldErrors` 计算该动作错误数，折叠态渲染角标。
  - 新增头部“展开/收起”按钮（`aria-expanded` 语义化）。
- `CycleTemplateEditor.tsx`（可选增强）：
  - 天级“全部展开 / 全部收起”快捷按钮，通过向所有 `ExerciseStructureEditor` 传 `expandedOverride` 实现。
- 保存反馈（可选增强）：
  - 保存校验失败时，自动展开第一个有错误的动作并滚动定位。

### 2.3 收益与风险

- 收益：默认只渲染卡片头部，DOM 数量大幅下降，滚动流畅度显著提升。
- 风险：**低**。纯展示层状态，不影响表单数据、撤销/重置、保存逻辑。
- 兼容：`exerciseMeta` 拉取逻辑不动；错误提示不丢失（折叠态角标 + 展开详情）。

## 3. 方案 B：时长单位拆分（秒 / 分钟）

### 3.1 产品决策

- 保留 `duration_seconds`：短项目（休息、平板支撑、静态保持）。
- 新增 `duration_minutes`：长项目（跑步、椭圆机、骑行、爬坡）。
- **放弃**“同一指标带单位切换 + 存储自动换算”的做法，理由：
  - 存储、统计、AI 分析需要规范单位，换算会引入不一致风险；
  - 与现有“封闭字典 + 键即语义”的设计冲突，改造成本高、收益低。

### 3.2 影响面（已逐项核实）

**后端（改动 3 个文件，无 DB 迁移）：**

| 文件 | 改动 |
|---|---|
| `plan/domain/model/MetricKey.java` | 新增 `DURATION_MINUTES("duration_minutes", "minutes")`。模板保存/快照校验（`ExerciseStructurePolicyService`）与响应单位推导（`resolveMetricUnit`）**自动放行/生效**。 |
| `workout/domain/service/WorkoutSessionPolicyDomainService.java` | `INTEGER_METRIC_KEYS` 集合加入 `"duration_minutes"`（实际值仅允许整数）。 |
| `aicoach/application/service/AiCoachToolSupportService.java` | `getTemplateGenerationConstraints().allowedMetricKeys` 加入 `DURATION_MINUTES`，让 AI 生成模板时可输出该键。 |

无需改动：
- 数据库：`metric_key` 无 CHECK 约束，加键不需要迁移 SQL。
- 打卡快照/装配器：单位均走枚举 `getUnit()`，自动返回 `minutes`。

**前端（改动 4 个文件）：**

| 文件 | 改动 |
|---|---|
| `cycle-template/types/cycle-template.ts` | `MetricKey` 联合类型加 `"duration_minutes"`。 |
| `workout/types/workout.ts` | `MetricKey` 联合类型加 `"duration_minutes"`。 |
| `cycle-template/lib/cycle-template-metric-config.ts` | 新增 meta：`label: "时长（分钟）"`、`unitLabel: "分钟"`、`step: "1"`、`min: 0`、`max: 1440`；同时把 `duration_seconds` 的 label 改为 `"时长（秒）"` 以便下拉框区分。 |
| `workout/lib/workout.ts` | `metricLabels` 加 `duration_minutes`；`integerMetricKeys` 加 `duration_minutes`。 |

**显示兼容（重点说明）：**

- 模板编辑页指标行 / 详情页 `formatMetricValue`：单位来自前端 meta（分钟/秒），正常。
- 打卡页计划值 chip 与只读页：单位来自后端 `metricUnit`（英文 `minutes` / `seconds`）。**现状 `duration_seconds` 已是英文 `seconds`，本方案不劣化**；若想顺带中文化（seconds→秒、minutes→分钟、count→次…），作为独立小改动在 4.3 评估。

**文档同步（4 份）：**

- `docs/interfaces/cycle_template_接口文档_v2.md` §2.7 参数字典：加 `duration_minutes`。
- `docs/interfaces/workout_接口文档.md`：指标说明补 `duration_minutes`。
- `docs/frontend/cycle_template_module/cycle_template_DDD.md`：MetricKey 列表与默认展示补键。
- `docs/backend/ai_coach_module/AI接入与提示词上下文设计.md`：AI 可用指标键清单补 `duration_minutes`。
- （可选）`docs/backend/cycle_template_module/动作参数模型改造后端影响分析.md`。

**测试：**

- 后端：既有 `duration_seconds` 用例保留；补 `duration_minutes` 通过策略校验 / 打卡整数校验用例。
- 前端：编辑页交互测试补“默认折叠 → 展开显示执行项 → 收起”；metric 配置可补 `duration_minutes` 元数据断言。

### 3.3 风险

- **中低**。纯新增键，旧数据不受影响。
- 注意点：AI 提示词、前后端字典必须**同步改**，否则 AI 输出 `duration_minutes` 时前端类型/选项不一致会导致下拉回显异常（后端枚举已放行，前端不同步会出现“合法键但无选项”）。
- `duration_minutes` 适用结构类型：建议 `set_based` 与 `single_segment` 都允许（与 `duration_seconds` 一致），主要使用场景是 `single_segment`。

## 4. 其他优化点（附加，按确认范围纳入）

| # | 优化点 | 说明 | 优先级 |
|---|---|---|---|
| 4.1 | 天级“全部展开/收起” | 多天切换时快速定位 | 建议纳入 |
| 4.2 | 折叠态错误角标 | 见 2.1，保证折叠后校验错误仍可见 | 建议纳入（随方案 A） |
| 4.3 | 打卡页单位中文化 | seconds→秒、minutes→分钟、count→次…（前端展示映射，不动后端） | 可选 |
| 4.4 | 保存失败自动展开首个错误动作 | 改善保存反馈 | 可选 |
| 4.5 | 卡片 `content-visibility:auto` | 长列表滚动渲染优化（CSS 一行） | 可选，低风险 |
| 4.6 | 执行项级折叠 | set_based 组数很多时可再折叠执行项 | 后置，低优先 |

1. **Commit 1（纯前端）**：方案 A 折叠 — `ExerciseStructureEditor.tsx`（+ 可选天级控制、错误角标）+ 交互测试。提交门禁：契约不变、测试通过、低风险审查。

3. **Commit 3（前端 + 契约）**：方案 B 前端 — 类型、metric 配置、workout 标签 + 前端测试。
