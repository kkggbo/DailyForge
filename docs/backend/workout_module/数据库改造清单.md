# Workout 模块数据库改造清单

> 版本：v1.1  
> 日期：2026-07-29  
> 对应文档：[workout_PRD.md](../../prd/workout_PRD.md)、[workout_接口文档.md](../../interfaces/workout_接口文档.md)  
> 对应迁移：`backend/src/main/resources/db/migration/V6__workout_schema_upgrade.sql`

---

## 1. 前提

当前数据库没有训练、循环或模板执行记录，因此本次采用**干净迁移**：

- 不需要兼容或回填旧 `training_sessions` 数据。
- 不保留旧的固定组执行表 `training_session_sets`。
- 不保留已经被三层明细表替代的 JSON 计划/实际快照字段。
- 迁移脚本必须在 V1 到 V5 已执行的基础上执行。

本次仍不改写旧迁移文件，而是新增 `V6__workout_schema_upgrade.sql`。

---

## 2. 改造目标

训练执行记录需要与 `cycle_template v2` 的三层模型对齐：

```text
training_sessions
  -> training_session_exercises
    -> training_session_exercise_items
      -> training_session_exercise_item_metrics
```

该结构支撑：

- 进入训练页自动创建或恢复当前 Day 的 `in_progress` session。
- 训练日和休息日统一打卡。
- `in_progress`、`completed`、`cancelled` 三种 session 状态。
- 当前循环内历史 Day、当前 Day、未来 Day 浏览。
- 计划值与实际值的结构化保存。
- 完成打卡后推进循环，循环结束后由用户选择下一步。

---

## 3. 表级改造

| 表 | 改造 | 说明 |
|------|------|------|
| `cycle_runs` | 新增 `cancelled_at`；删除旧 `archived_at`；补充状态注释；新增 `(user_id, status)` 索引 | 支持未完成循环因切换模板而取消 |
| `user_active_cycles` | 不改表 | 循环完成后保留当前 run 引用，通过 `cycle_runs.status = completed` 判断循环结束页 |
| `training_sessions` | 新增状态、类型、模板/Day 名称快照、更新时间；删除 `session_no`；增加 run/day 唯一约束 | 支持自动初始化幂等、休息日和历史展示 |
| `training_session_exercises` | 新增 `structure_type`；动作状态允许为空；删除旧 JSON 快照字段 | 进行中保存允许未标记状态，结构由关系表完整表达 |
| `training_session_exercise_items` | 新建 | 保存训练动作下的组/段快照 |
| `training_session_exercise_item_metrics` | 新建 | 保存计划参数和实际参数 |
| `training_session_sets` | 直接删除 | 固定组模型无法支撑 `single_segment` 有氧动作，且当前无历史数据 |

---

## 4. 详细设计

### 4.1 `cycle_runs`

新增：

- `cancelled_at DATETIME(3) NULL`

状态语义：

- `active`：当前正在执行。
- `completed`：当前循环所有 Day 已完成打卡。
- `cancelled`：未完成循环因用户切换模板等原因结束。

旧 `archived_at` 字段直接删除。当前数据库没有执行记录，循环结束只使用 `status = completed` 表达，不保留旧归档语义。

新增索引：

- `idx_cycle_runs_user_status (user_id, status)`

### 4.2 `training_sessions`

新增字段：

- `status VARCHAR(32) NOT NULL DEFAULT 'in_progress'`
- `session_type VARCHAR(32) NOT NULL DEFAULT 'workout'`
- `template_name_snapshot VARCHAR(128) NOT NULL`
- `day_name_snapshot VARCHAR(64) NOT NULL`
- `updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)`

删除字段：

- `session_no`

新增约束：

- `uk_training_sessions_cycle_run_day (cycle_run_id, day_index)`

这个唯一约束是 W2 自动初始化的最终幂等保障：同一个用户循环中的同一天只能有一条 session。

新增索引：

- `idx_training_sessions_cycle_run_status (cycle_run_id, status)`：模板切换时取消进行中 session。
- `idx_training_sessions_user_completed_at (user_id, completed_at, started_at)`：最近训练记录排序。

### 4.3 `training_session_exercises`

新增：

- `structure_type VARCHAR(32) NOT NULL`

调整：

- `exercise_status` 从 `NOT NULL` 改为允许 `NULL`。
  - W4 保存进行中内容时可以不选状态。
  - W5 完成训练日时再由业务层校验所有动作状态。

删除：

- `planned_snapshot_json`
- `actual_summary_json`

动作、执行项与参数快照全部由关系表保存，不再保留两套权威数据源。

### 4.4 `training_session_exercise_items`

字段：

- `id`
- `session_exercise_id`
- `item_index`
- `item_type`
- `item_name_snapshot`
- `note_snapshot`
- `sort_order`
- `created_at`
- `updated_at`

约束和索引：

- `UNIQUE(session_exercise_id, item_index)`
- `KEY(session_exercise_id, sort_order)`

### 4.5 `training_session_exercise_item_metrics`

字段：

- `id`
- `session_exercise_item_id`
- `metric_key`
- `planned_value_number`
- `actual_value_number`
- `sort_order`
- `created_at`
- `updated_at`

约束和索引：

- `UNIQUE(session_exercise_item_id, metric_key)`
- `KEY(session_exercise_item_id, sort_order)`

`planned_value_number` 和 `actual_value_number` 都允许为空。单位不落库，由后端按照 `metric_key` 推导。

## 5. 索引映射

| 场景 | 索引 |
|------|------|
| 自动初始化当前 Day | `uk_training_sessions_cycle_run_day` |
| 模板切换取消进行中 session | `idx_training_sessions_cycle_run_status` |
| 当前循环 Day 导航 | `uk_training_sessions_cycle_run_day` 左前缀 |
| 最近训练记录 | `idx_training_sessions_user_completed_at` |
| session 动作列表 | 既有 `idx_training_session_exercises_session_sort` |
| session 执行项列表 | `idx_training_session_exercise_items_exercise_sort` |
| session 参数列表 | `idx_training_session_exercise_item_metrics_item_sort` |
| 查询用户的 active run | `idx_cycle_runs_user_status` |

## 6. 跨模块同步

迁移后需要同步修改：

1. 模板切换时：未完成旧 `cycle_run` 更新为 `cancelled` 并写入 `cancelled_at`。
2. 同时把旧 run 下所有 `in_progress training_sessions` 更新为 `cancelled`。
3. 已完成 session 不能被取消或删除。
4. `cycle_template_接口文档_v2.md` 中旧 run 切换为 `completed` 的描述应改为：未完成 run 改为 `cancelled`，已完成 run 保持 `completed`。
5. 后端 Entity、Mapper、ErrorCode、H2 测试建表脚本及相关测试必须同步。

---

## 7. 执行顺序

1. 确认数据库没有训练相关记录。
2. 手动执行 `V6__workout_schema_upgrade.sql`。
3. 使用 `SHOW CREATE TABLE` 检查新增字段、唯一约束和两张新表。
4. 再开始 workout 后端实体、Mapper、Service 和接口实现。

此脚本会删除 `training_session_sets`、`planned_snapshot_json` 和 `actual_summary_json`。如果未来数据库已有训练记录，不能直接复用该脚本，必须重新设计兼容迁移。
---

## 8. V6 部分执行失败恢复（仅当前数据库）

若首次手动执行 V6 时，在 `training_sessions` 的 `DROP INDEX idx_training_sessions_template_session_no` 处出现外键依赖错误，说明旧复合索引同时支撑了 `fk_training_sessions_template_id`。

当前数据库的客户端已经继续执行后续语句，因此不要重新执行完整 V6。改为只执行：[V6部分执行恢复脚本.sql](V6部分执行恢复脚本.sql)。

该恢复脚本会先新增 `idx_training_sessions_template_id (template_id)`，再完成此前失败的 `training_sessions` 改造。它只适用于本次部分执行状态；全新环境仍应直接执行修正后的 `V6__workout_schema_upgrade.sql`。
