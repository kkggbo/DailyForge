## 1. 文档目标

本文档用于定义 DailyForge `workout` 模块在 MVP 阶段的产品需求，重点解决用户在已有激活循环模板后，如何查看今日训练、记录实际完成情况、完成训练打卡、推进当前循环，并在循环结束后决定下一步。

本文档服务于：

- 后续 `workout` 接口文档设计
- 后端训练打卡模块 DDD 与数据库改造
- 前端训练执行页、训练详情页、循环结束页设计
- 与 `cycle_template`、历史统计、未来 AI 总结能力的衔接

---

## 2. 模块定位

`cycle_template` 负责定义“计划怎么练”，`workout` 负责记录“实际怎么练”。

`workout` 模块不是自由训练日志，也不是完整训练分析系统。MVP 的重点是打通以下闭环：

```text
当前激活模板 -> 自动初始化当前 Day 会话 -> 记录实际情况
-> 完成打卡 -> 推进循环 -> 循环结束后由用户选择下一步
```

本模块应帮助用户完成两件事：

- 当下执行：清楚知道今天该练什么，并能低成本记录实际完成情况。
- 后续调整：为用户或未来 AI 分析提供本轮训练的实际数据、失败原因、身体感受和调整线索。

---

## 3. 已确认关键决策

- 一个用户同一时间只能有一个激活循环模板。
- 用户进入训练页时，默认展示当前激活模板中最新未打卡的 Day。
- 训练页不展示“开始训练”按钮；进入默认 Day 时，前端自动初始化或恢复该 Day 的 `in_progress` session。
- 前端可以浏览当前循环内的历史 Day 和未来 Day；浏览不改变当前循环进度，也不会为未来 Day 创建 session。
- 用户完成当前 Day 后，后端立即推进循环，但前端保持展示当前已完成 Day；仅在用户手动切换、刷新或重新进入训练页时展示最新未打卡 Day。
- 训练日不强制绑定自然日期，系统按打卡顺序推进 Day。
- 每个动作必须标记状态后，才能完成当天训练打卡。
- 失败原因建议填写，但 MVP 不强制。
- 休息日也需要打卡，打卡后才能推进到下一个 Day。
- 当前循环完成后，不自动根据同一模板创建下一轮。
- 循环结束后给用户三个选择：再次使用当前模板、选择其他模板、AI 分析/生成模板占位。
- 训练会话状态需要包含 `in_progress`、`completed`、`cancelled`。
- 用户中途切换模板时，旧循环标记为 `cancelled`，已有训练记录保留。
- 已完成训练记录第一版只读，不支持编辑。
- 第一版不支持撤销最近一次打卡。
- 第一版不支持临时添加计划外动作。

## 4. 目标用户

- 新手健身用户：希望系统告诉自己今天该练什么，并通过简单的完成/跳过/未完成标记养成训练习惯。
- 有经验训练者：希望记录实际重量、次数、时长、RPE、失败原因和训练感受，用于后续调整下一轮计划。

## 5. 范围

### 5.1 本期包含

- 获取今日训练上下文。
- 无激活模板时展示空状态并引导去模板页。
- 今日训练日展示计划动作和计划参数。
- 今日休息日展示休息日状态并支持休息日打卡。
- 进入训练页时自动创建或返回当前 Day 的进行中训练会话。
- 在当前循环内浏览历史训练记录和未来待训练内容。
- 保存进行中训练会话。
- 按动作记录实际执行情况。
- 按动作标记完成、部分完成、跳过、未完成。
- 记录动作级失败原因与感受/备注。

- 真实 AI 周期总结或 AI 自动生成新模板。
- 饮食建议联动。

- 临时添加计划外动作。
- 已完成训练记录编辑。
- 撤销最近一次打卡。
- 训练计时器。
- 组间休息倒计时。
- 复杂历史统计图表。
- 可穿戴设备同步。
- 多人训练、教练端管理。

## 6. 核心业务对象

### 6.1 Workout

产品侧统一称为 `workout`，表示用户一次训练执行体验。

它可以对应：

- 一个有动作的训练日。
- 一个没有动作的休息日打卡。

### 6.2 Cycle Run

`cycle_run` 表示某个模板的一轮实际执行。

状态建议包含：

- `active`：当前正在执行。
- `completed`：本轮所有 Day 已完成打卡。
- `cancelled`：本轮未完成，但因用户切换模板等原因被中止。

### 6.3 Training Session

`training_session` 表示一次具体打卡记录。

它必须绑定：

- 用户。
- 当前 `cycle_run`。
- 模板。
- 模板版本。
- 模板日。
- `dayIndex`。

状态包含：

- `in_progress`：已开始但尚未完成。
- `completed`：已完成打卡。
- `cancelled`：已取消，数据保留但不视为完成打卡。

### 6.4 Training Session Exercise

`training_session_exercise` 表示一次训练中某个动作的实际执行记录。

它需要保留：

- 模板动作来源。
- 动作名称快照。
- 计划结构快照。
- 实际完成结构。
- 动作状态。
- 失败原因。
- 动作感受。
- 调整备注。

### 6.5 执行项与参数

训练打卡应复用 `cycle_template v2` 的三层结构：

```text
动作 exercise -> 执行项 item -> 参数 metric
```

示例：

- 卧推：动作 -> 第 1 组 / 第 2 组 -> 重量、次数、RPE。
- 跑步：动作 -> 第 1 段 -> 时长、距离、配速、坡度。

## 7. 页面与交互流程

### 7.1 训练工作台

建议入口：

- `/workout`

训练页是围绕当前循环 Day 的训练工作台，而非“先点击开始、再进入训练”的两阶段页面。

页面需要覆盖以下状态：

- 无激活模板。
- 当前循环正在执行，默认展示最新未打卡 Day。
- 当前 Day 是训练日。
- 当前 Day 是休息日。
- 当前 Day 已存在进行中训练。
- 当前循环已完成，等待用户选择下一步。

### 7.2 默认进入与自动初始化

用户首次进入、刷新或离开后重新进入 `/workout` 时：

1. 前端读取当前训练上下文，确认当前循环状态和默认 Day。
2. 若当前循环为 `active`，默认选中最新未打卡的 `currentDayIndex`。
3. 前端自动调用“初始化当前 Day session”接口：
   - 若不存在 session，后端创建 `in_progress` session 并生成计划快照。
   - 若已有 `in_progress` session，后端直接返回已有 session。
4. 用户直接看到可编辑的训练内容，不需要点击“开始训练”。

自动初始化只适用于默认进入的当前 Day：

- 浏览历史 Day 时不创建新 session。
- 浏览未来 Day 时不创建新 session。
- 已完成 Day 不创建新 session。

### 7.3 Day 浏览与展示状态

训练页应提供当前循环内的 Day 导航。前端可采用前一天 / 后一天按钮、Day Tab 或同等交互形式；具体视觉实现由前端决定。

前端需要维护：

- `currentDayIndex`：后端返回的真实循环进度，不由浏览行为改变。
- `selectedDayIndex`：当前页面正在查看的 Day，仅用于前端展示。

不同 Day 的展示规则：

| Day 类型 | 判断 | 展示模式 | 是否可编辑 | 是否创建 session |
|------|------|------|:---:|:---:|
| 已完成 Day | `dayIndex < currentDayIndex`，或刚完成的当前 Day | 历史训练记录 | 否 | 否 |
| 当前 Day | `dayIndex = currentDayIndex` 且循环为 `active` | 当前可打卡内容 | 是 | 默认进入时自动创建/恢复 |
| 未来 Day | `dayIndex > currentDayIndex` | 待训练计划预览 | 否 | 否 |

说明：

- 浏览范围仅限当前 `cycle_run` 内的 `1 ~ cycleLength`。
- 跨循环的历史记录由“最近训练记录”入口查看，不混入当前 Day 导航。
- 未来 Day 的计划修改仍应回到 `cycle_template` 模块完成。

### 7.4 无激活模板状态

当用户没有激活模板时：

- 页面展示空状态。
- 提示用户需要先创建或启用训练模板。
- 提供跳转到模板页的入口。
- 不允许创建自由训练打卡。

### 7.5 当前训练日

当当前 Day 有动作时，页面展示：

- 当前模板名称。
- 当前循环轮次。
- 当前 Day 名称。
- 当前 Day Index。
- Day 导航状态。
- 计划动作列表。
- 每个动作的计划执行项与参数。
- 直接可填写的实际执行区域。

### 7.6 当前休息日

当当前 Day 没有任何动作时，系统视为休息日。

用户可以：

- 查看休息日状态。
- 填写可选备注。
- 点击“完成休息日打卡”。
- 推进到下一个 Day。

休息日必须打卡后才能推进循环。

### 7.7 完成后的停留行为

用户完成当前 Day 打卡后：

- 后端立即推进 `currentDayIndex`，或在最后一天将当前 `cycle_run` 标记为 `completed`。
- 前端保持 `selectedDayIndex` 为刚完成的 Day，不自动跳转。
- 页面展示“本 Day 已完成”等完成态信息，并切换为只读。
- 用户可以手动通过 Day 导航查看下一个 Day、之前 Day 或未来 Day。
- 用户刷新页面或重新进入训练页后，前端重新按后端 `currentDayIndex` 默认展示最新未打卡 Day。
- 如果刚完成的是周期最后一天，当前页面展示“本 Day 已完成 + 当前循环已完成”；刷新或重新进入后展示循环结束页。

### 7.8 最近训练记录列表

第一版建议只提供简单列表：

- 训练日期。
- 模板名称。
- Day 名称。
- 训练状态。
- 完成时间。

该列表可以先放在 `workout` 页下方，后续再迁移或扩展到历史统计模块。

### 7.9 训练记录详情页

建议路径：

- `/workout/history/{sessionId}`

第一版只读，不允许编辑。

## 8. 训练会话规则

### 8.1 自动初始化当前 Day

用户进入训练页、刷新页面或重新进入页面时，前端会自动初始化默认 Day：

- 如果当前 Day 没有进行中的 session，则创建一个 `in_progress` session。
- 如果当前 Day 已有 `in_progress` session，则返回已有 session。
- 如果当前 Day 已有 `completed` session，则不重复创建。
- session 创建时必须保存必要快照，避免模板后续修改影响历史记录。
- 用户确认保存 active 模板后，如果当前 Day 已创建 `in_progress` session，系统会同步刷新为最新模板快照。
- 刷新会覆盖该 session 中的整体备注、动作状态、失败原因、动作反馈和实际参数；前端必须先明确提示并要求用户确认，后端必须通过确认字段拦截未确认请求。
- 自动初始化不适用于用户手动浏览的历史 Day 或未来 Day。

### 8.2 进行中保存

进行中 session 支持用户手动保存。

产品语义：

- 保存的是当前页面中的最新填写结果。
- 未保存修改可以只存在前端本地状态。
- 用户刷新或重新进入页面时，应读取后端最近一次已保存内容。
- 接口层建议采用“完整保存当前 session 内容”的语义，避免复杂 patch 合并。

### 8.3 完成打卡

用户点击“完成打卡”前：

- 每个动作都必须选择动作状态。
- `completed` 动作默认视为按计划完成；仅当实际值与计划不一致时填写实际数据。
- `partial_completed` 动作应尽量填写实际完成内容。
- `skipped` 和 `failed` 可以不填写实际参数。
- 失败原因建议填写，但 MVP 不强制。
- 训练备注可选。

完成后：

- session 状态变为 `completed`。
- 写入完成时间。
- 当前循环推进到下一个 Day，或进入循环结束状态。
- 已完成 session 第一版只读。

### 8.4 取消

`cancelled` 是底层状态，第一版主要由“用户中途切换模板”触发。

规则：

- 取消不等于删除。
- 已填写数据保留。
- 已完成 session 不应被取消。
- `cancelled` session 不计入完成率。
- 历史记录中可以展示为“已取消”。

第一版不强制提供用户手动取消训练按钮；如前端需要，可以作为次级能力讨论。

## 9. 动作状态与原因

### 9.1 动作状态

每个动作必须标记一个状态：

- `completed`：正常完成。
- `partial_completed`：部分完成。
- `skipped`：跳过。
- `failed`：未完成。

### 9.2 失败 / 跳过原因

建议 MVP 使用固定枚举：

- `too_tired`：力竭 / 状态差。
- `equipment_unavailable`：器械被占用。
- `pain_or_discomfort`：疼痛 / 不适。
- `time_not_enough`：时间不够。
- `plan_too_hard`：计划强度过高。
- `other`：其他。

当选择 `other` 时，用户可以填写自由文本备注。

## 10. 实际数据记录规则

### 10.1 计划值与实际值

打卡页需要同时展示计划值和填写实际值。

示例：

```text
计划：卧推 60kg x 8 次
实际：卧推 50kg x 6 次
感受：热身俯卧撑过多导致三头力竭
```
实际值录入采用“按需覆盖”交互：

- 默认展示计划参数，不要求用户逐项重复填写实际值。
- 用户仅在实际执行与计划不一致时，打开当前执行项的“记录实际值”输入区并填写偏离参数。
- 未填写实际值且动作状态为 `completed` 时，系统按计划值固化该执行项的实际值。
- `partial_completed`、`skipped`、`failed` 未填写实际值时保持为空，不应伪造为计划完成。
- 所有实际数值必须为非负数；可使用小数的参数最多保留 2 位小数，计数、秒数等整数型参数不允许小数。

动作卡片采用渐进披露：

- 动作状态选择固定放在动作卡片底部。
- 失败/跳过原因仅在动作状态不是 `completed` 时展示。
- “其他”原因提示用户在“感受/备注”中补充说明，但不强制。
- “感受/备注”默认折叠，用户主动点击后显示单个合并输入框。
- 训练整体层面仅保留一个默认展示、允许为空的“训练备注”输入框。

### 10.2 与计划结构对齐

实际填写结构应与创建 session 时的计划结构对齐：

- 计划有几个动作，默认展示几个动作。
- 计划有几个执行项，默认展示几个实际执行项。
- 用户不能临时新增计划外动作。
- 第一版不要求支持新增额外执行项。

### 10.3 不同动作结构

`set_based` 动作：

- 按组填写。
- 常用参数包括重量、次数、RPE、休息时间、备注。

`single_segment` 动作：

- 按段填写。
- 常用参数包括时长、距离、速度、配速、坡度、强度、备注。

## 11. 循环推进规则

### 11.1 普通推进

当用户完成当前 Day 打卡后：

- 如果 `currentDayIndex < cycleLength`，则 `currentDayIndex + 1`，当前 `cycle_run` 保持 `active`。
- 如果 `currentDayIndex = cycleLength`，则当前 `cycle_run` 标记为 `completed`，当前循环进入结束状态，不自动创建下一轮。

### 11.2 循环结束后的用户选择

当前循环完成后，用户需要主动选择下一步：

1. 以当前模板再次开启新的循环训练。
2. 选择其他模板开始新的循环训练。
3. 让 AI 根据本轮训练表现生成总结、建议或新模板。

MVP 中第三项只作为占位入口：

- 不调用真实 AI。
- 不生成真实建议。
- 可提示“AI 分析能力暂未开放”。

### 11.3 再次使用当前模板

用户选择“以当前模板再次开启新的循环训练”后：

- 当前模板继续保持 `active`。
- 创建新的 `cycle_run`。
- 新 `runNo = 上一轮 runNo + 1`。
- `currentDayIndex` 重置为 `1`。
- 今日训练页展示新一轮 Day 1。

### 11.4 选择其他模板

用户选择“选择其他模板开始新的循环训练”后：

- 跳转到模板页面。
- 用户按 `cycle_template` 模块规则启用其他模板。
- 启用新模板时会创建新的 `cycle_run`。

### 11.5 为什么不自动开启下一轮

不自动开启下一轮是产品规则。

原因：

- 用户完成一个循环后可能需要调整训练强度。
- 用户可能发现某些动作引发疼痛或不适。
- 用户可能希望根据本轮感受更换模板。
- 后续 AI 总结能力需要在循环结束点介入。

## 12. 与 Cycle Template 模块的关系

### 12.1 依赖内容

`workout` 模块依赖 `cycle_template` 提供：

- 当前激活模板。
- 当前运行实例。
- 当前模板版本。
- 当前 Day Index。
- 当前 Day 的动作结构。

### 12.2 已打卡天锁定

训练打卡完成后，对应 Day 应视为已执行。

模板模块中的规则继续生效：

- 已打卡天不能修改。
- 当前天及未来天可以修改。

### 12.3 模板切换

如果用户在当前循环未完成时启用其他模板：

- 旧 `cycle_run` 标记为 `cancelled`。
- 旧模板状态变为 `inactive`。
- 进行中的 `training_session` 标记为 `cancelled`。
- 已完成训练记录保留。
- 新模板创建新的 `cycle_run`，并从 Day 1 开始。

如果旧 `cycle_run` 已经是 `completed`，用户再启用其他模板不属于“取消旧循环”，而是普通切换模板。

## 13. 数据影响

### 13.1 当前已有表

当前数据库已存在：

- `cycle_runs`
- `user_active_cycles`
- `training_sessions`
- `training_session_exercises`
- `training_session_sets`

### 13.2 明确需要改造的点

为满足本 PRD，后续数据库改造至少需要考虑：

- `training_sessions` 增加 `status` 字段，用于区分 `in_progress`、`completed`、`cancelled`。
- `training_sessions` 增加休息日语义字段，例如 `session_type` 或 `is_rest_day`。
- `training_sessions` 增加模板名称、Day 名称等必要快照字段。
- `cycle_runs.status` 支持 `active`、`completed`、`cancelled`。
- `training_session_exercises` 保留动作状态、失败原因、感受/备注；现有拆分字段可在实现层兼容保留，但新接口不再拆分暴露。
- 新增训练实际执行项表，例如 `training_session_exercise_items`。
- 新增训练实际执行项参数表，例如 `training_session_exercise_item_metrics`。
- 当前无历史记录，直接删除 `training_session_sets` 与旧 JSON 执行快照字段。

### 13.3 删除旧 `training_session_sets`

当前数据库没有训练记录，因此不需要兼容旧固定组模型。

原因：

- 该表天然假设所有动作都是按组训练。
- 不适配跑步、椭圆机、爬坡等 `single_segment` 动作。
- 与 `cycle_template v2` 三层动作结构不一致。

改造结果：

- 保留 `training_sessions` 作为 session 主表。
- 保留 `training_session_exercises` 作为动作头表。
- 新增 `training_session_exercise_items`。
- 新增 `training_session_exercise_item_metrics`。
- 删除 `training_session_sets`、`planned_snapshot_json` 和 `actual_summary_json`，避免新旧两套执行模型并存。

### 13.4 快照要求

训练记录必须保存必要快照，避免模板后续修改影响历史记录展示。

至少需要保存：

- 模板名称快照。
- Day 名称快照。
- 动作名称快照。
- 计划结构快照。
- 实际完成结构。

## 14. 接口建议范围

后续接口文档建议至少包含：

- `GET /api/workouts/context`：获取当前训练工作台上下文、真实进度和 Day 导航摘要。
- `POST /api/workouts/current-day/session`：自动创建或返回默认当前 Day 的进行中 session。
- `GET /api/workouts/days/{dayIndex}`：按 Day 浏览当前循环中的历史记录、当前打卡内容或未来计划预览。
- `PUT /api/workouts/sessions/{sessionId}`：保存进行中训练会话。
- `POST /api/workouts/sessions/{sessionId}/complete`：完成训练打卡并推进循环。
- `GET /api/workouts/sessions/{sessionId}`：查看训练记录详情。
- `GET /api/workouts/recent`：查看最近训练记录。
- `POST /api/workouts/cycles/current/restart`：当前循环完成后，使用当前模板开启下一轮。

说明：

- `cancelled` 状态第一版主要由模板切换流程触发，不强制暴露用户手动取消接口。
- “自动初始化”是前端进入默认 Day 后自动发起的幂等 `POST` 请求，不使用有副作用的 `GET` 请求。
- 如果后端为了内部解耦提供取消接口，应在接口文档中标记为内部使用或谨慎开放。

## 15. 异常与边界场景

### 15.1 无激活模板

如果用户没有激活模板：

- 今日训练页展示空状态。
- 前端提供去模板页创建或启用模板的入口。
- 后端返回明确的空状态或错误码。

### 15.2 当前循环已完成

如果当前循环已完成但用户尚未选择下一步：

- 今日训练页展示循环结束状态。
- 不展示新的训练 Day。
- 不自动创建下一轮。

### 15.3 重复自动初始化

如果默认当前 Day 已存在 `in_progress` session：

- 前端自动初始化时返回已有 session。
- 不重复创建。

### 15.4 重复完成打卡

如果当前 Day 已经有 `completed` session：

- 不允许再次完成同一个 Day。
- 前端默认应展示下一个 Day 或循环结束页。

### 15.5 提交过期模板版本

如果用户打开训练页后，当前 active 模板未来天被修改：

- 已创建的历史 completed / cancelled session 使用创建或完成时快照。当前 Day 的 `in_progress` session 作为例外，会在用户确认保存 active 模板时刷新并覆盖未完成填写记录。
- 未创建 session 的后续 Day 使用最新 active 版本。

### 15.6 训练中切换模板

如果存在 `in_progress` session 时切换模板：

- 当前 session 标记为 `cancelled`。
- 当前 cycle run 标记为 `cancelled`。
- 已完成记录保留。

## 16. 验收标准

### 16.1 今日训练与 Day 浏览

- Given 用户有激活模板，when 首次进入、刷新或重新进入训练页，then 页面默认展示最新未打卡 Day。
- Given 默认当前 Day 没有进行中 session，when 前端进入训练页后自动初始化，then 系统创建 `in_progress` session，页面无需展示“开始训练”按钮。
- Given 默认当前 Day 已有进行中 session，when 前端自动初始化，then 系统返回已有 session。
- Given 用户无激活模板，when 进入训练页，then 页面展示去模板页的引导。
- Given 当前 Day 没有动作，when 进入训练页，then 页面展示休息日打卡状态。
- Given 用户查看已完成 Day，when 切换 Day 导航，then 页面展示只读历史记录且不创建 session。
- Given 用户查看未来 Day，when 切换 Day 导航，then 页面展示只读计划预览且不创建 session。

### 16.2 保存与完成后的停留

- Given 用户保存进行中 session，when 重新进入页面，then 页面回显最近一次已保存内容。
- Given 用户完成当前 Day，when 后端推进 `currentDayIndex` 后，then 前端仍展示刚完成的 Day 及完成态信息，不自动跳转。
- Given 用户完成当前 Day 后刷新或重新进入训练页，when 当前循环仍为 `active`，then 页面展示新的最新未打卡 Day。

### 16.3 动作打卡

- Given 某个动作未标记状态，when 用户点击完成打卡，then 系统阻止提交。
- Given 所有动作都已标记状态，when 用户点击完成打卡，then session 可以完成。
- Given 动作为 `skipped` 或 `failed`，when 用户未填写实际参数，then 仍允许完成打卡。
- Given 用户填写失败原因和感受，when 查看训练详情，then 页面能看到对应记录。

### 16.4 休息日打卡

- Given 当前 Day 是休息日，when 用户点击完成休息日打卡，then 系统推进到下一个 Day。
- Given 休息日是周期最后一天，when 用户完成休息日打卡，then 当前循环进入完成状态。

### 16.5 循环完成

- Given 用户完成周期最后一天，when 打卡成功，then 当前 cycle run 标记为 `completed`。
- Given 当前 cycle run 已完成，when 用户回到训练页，then 页面展示循环结束页。
- Given 当前 cycle run 已完成，when 用户未选择下一步，then 系统不会自动创建下一轮。
- Given 用户选择再次使用当前模板，when 操作成功，then 系统创建新 cycle run 并从 Day 1 开始。

### 16.6 循环取消

- Given 当前循环未完成，when 用户启用其他模板，then 旧 cycle run 标记为 `cancelled`。
- Given 存在进行中 session，when 用户启用其他模板，then 该 session 标记为 `cancelled`。
- Given 旧循环中已有 completed session，when 用户切换模板，then 已完成记录继续可查看。

## 18. 结论

`workout` 模块是 DailyForge 训练闭环真正落地的关键模块。

本期设计遵循以下原则：

1. 基于当前激活模板执行，不做自由训练。
2. 训练记录必须保留历史快照，不受模板后续修改影响。
3. 每个动作必须标记状态，才能完成当天打卡。
4. 休息日也需要打卡推进循环。
5. 当前循环结束后不自动开启下一轮，由用户决定下一步。
6. 中途切换模板时取消旧循环，但保留已有记录。
7. 训练记录结构应对齐 `cycle_template v2` 的三层动作参数模型。
