# DailyForge 账号管理 PRD

> 版本：v0.1
> 日期：2026-09-02
> 状态：待评审
> 模块名称：`auth`（账号管理）

---

## 1. 文档目标

定义用户账号管理三项功能：**修改用户名**、**修改密码**、**密码找回（忘记密码）**。本文档服务于接口文档、DDD、前后端实现与验收。

---

## 2. 背景与目标

DailyForge 目前只支持注册/登录/退出/兑换邀请码，缺少账号资料维护能力。本期补齐：

- 用户可修改用户名（唯一，不与他人重复）。
- 用户可修改密码（需验证旧密码）。
- 用户忘记密码时可通过邮箱验证码重置。

---

## 3. 目标用户

- 所有已登录用户（修改用户名 / 修改密码）。
- 忘记密码的未登录用户（密码找回）。

---

## 4. 功能需求

### 4.1 修改用户名

- 入口：账号设置页（登录态）。
- 规则：
  - 非空。
  - 长度 2~20 位。
  - 字符：中文 / 字母 / 数字 / 下划线。
  - **唯一**：不能与其它用户同名（判重**不区分大小写**，依赖 `user_name` 唯一索引与 `utf8mb4_unicode_ci` 排序规则）。
- 成功后返回最新的 `CurrentUserResponse`，前端同步更新登录态用户名。

### 4.2 修改密码

- 入口：账号设置页（登录态）。
- 规则：
  - 需输入**旧密码**并验证正确。
  - 新密码 6~18 位（与注册规则一致）。
  - 两次新密码输入一致。
  - 新密码不能与旧密码相同。
- 本期**不使其它已登录会话失效**（JWT 无状态，旧 token 在有效期内仍可用，后续可加 token 版本机制）。

### 4.3 密码找回（忘记密码）

- 入口：登录页「忘记密码」→ 独立流程页（无需登录）。
- 流程：
  1. 用户输入邮箱 → 请求发送验证码。
  2. 后端生成 6 位数字验证码，存 Redis（TTL 10 分钟），通过 **QQ 邮箱 SMTP** 发送邮件。
  3. 用户输入验证码 + 新密码 + 确认密码 → 校验通过后重置密码。
- 安全规则：
  - **防枚举**：无论邮箱是否存在，发送验证码接口统一返回成功（不发邮件给不存在的邮箱，但不暴露差异）。
  - 同邮箱 **60 秒内不重复发送**。
  - 验证码错误最多 **5 次**，超限即作废（删除）。
  - 验证码 10 分钟过期。

## 5. 接口契约（摘要）

| 方法 | 路径 | 登录 | 请求体 | 说明 |
| --- | --- | --- | --- | --- |
| PUT | `/api/auth/username` | 是 | `{ userName }` | 修改用户名，返回 `CurrentUserResponse` |
| POST | `/api/auth/password/change` | 是 | `{ oldPassword, newPassword, confirmPassword }` | 修改密码 |
| POST | `/api/auth/password/forgot-code` | 否 | `{ email }` | 发送找回验证码 |
| POST | `/api/auth/password/reset` | 否 | `{ email, code, newPassword, confirmPassword }` | 校验验证码并重置密码 |

（详细字段与响应见接口文档。）

## 6. 邮件与验证码（QQ 邮箱 SMTP）

- 后端新增 `spring-boot-starter-mail` 依赖。
- SMTP 配置（通过环境变量注入，不硬编码）：
  - 主机：`smtp.qq.com`
  - 端口：`465`（SSL，或 587 STARTTLS）
  - 账号：发件 QQ 邮箱
  - 密码：**QQ 邮箱授权码**（用户已持有）
- 邮件正文：验证码 + 10 分钟有效期提示。
- 验证码存储：Redis，key=`forgot:{email}`，TTL 10 分钟，值含验证码与尝试计数。
- 发送失败：返回业务错误（`EMAIL_SEND_FAILED`），不落验证码。

## 7. 前端

- 新增「账号设置」页（`/account`）：修改用户名（输入框 + 唯一性错误提示）、修改密码（旧密码 + 新密码 + 确认，含强度/一致性校验）。
- 个人资料页 / AppShell 导航增加「账号设置」入口。
- 登录页加「忘记密码」链接 → 新增 `/forgot-password` 流程页：
  - 步骤 1：输入邮箱 → 发送验证码（60s 倒计时防刷）。
  - 步骤 2：输入验证码 + 新密码 + 确认 → 提交重置 → 成功跳转登录页。
- `AuthProvider`：修改用户名成功后更新 `currentUser.userName`。

## 9. 错误码（新增）

| 错误码 | 说明 |
| --- | --- |
| `USERNAME_ALREADY_EXISTS` | 用户名已被占用（409） |
| `USERNAME_INVALID` | 用户名长度/字符非法（400） |
| `PASSWORD_INCORRECT` | 旧密码错误（400） |
| `PASSWORD_SAME_AS_OLD` | 新密码与旧密码相同（400） |
| `FORGOT_CODE_INVALID` | 验证码错误（400） |
| `FORGOT_CODE_EXPIRED` | 验证码过期（400） |
| `FORGOT_CODE_ATTEMPTS_EXCEEDED` | 验证码尝试超限（400） |
| `FORGOT_CODE_TOO_FREQUENT` | 发送过于频繁（400/429） |
| `EMAIL_SEND_FAILED` | 邮件发送失败（502/500） |

## 10. 范围

### 本版包含
- 后端：用户名修改、密码修改、密码找回（含邮件服务、Redis 验证码、V10 唯一索引）、错误码、测试。
- 前端：账号设置页、忘记密码流程页、登录页入口、AuthProvider 更新。
- 文档：接口文档、DDD、changelog。

### 本版不含
- 修改邮箱 / 邮箱二次验证。
- 改密后强制其它会话失效（token 版本机制）。
- 双因素认证。

---

## 11. 验收标准

1. 修改用户名：成功更新；与其它用户重名被拒（不区分大小写）；长度/字符非法被拒；成功后登录态同步新用户名。
2. 修改密码：旧密码错误被拒；两次不一致被拒；新密码与旧密码相同被拒；成功后可用新密码登录、旧密码不可登录。
3. 找回密码：
   - 发送验证码：合法邮箱返回成功；**不存在的邮箱同样返回成功**（防枚举）；同邮箱 60 秒内重发被拒。
   - 重置：正确验证码 + 合法新密码 → 重置成功，新密码可登录；错误验证码累计 5 次作废；过期验证码被拒。
4. 邮件：能通过 QQ 邮箱 SMTP 收到验证码邮件。
5. 前端：账号设置页、忘记密码流程页、登录页入口均可用，交互与错误提示符合预期。
6. 后端 `mvn test`、前端 `pnpm test` 通过；契约联调校验通过。
