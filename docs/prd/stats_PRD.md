## 1. 文档目标

定义「训练统计 + 身体指标趋势」模块的产品需求。统计用户**打卡过的所有训练记录**（不限周期/会话是否完成），按时间与动作分类展示各项数据；并提供身体指标随时间变化的折线图。

本文档服务于接口文档、DDD、前后端实现与验收。

---

## 2. 背景与目标

DailyForge 已积累训练打卡（`training_session_exercise_item_metrics.actual_value`）与身体指标记录（`body_metric_logs`）。统计模块让用户直观看到「练了什么、练了多少、变化趋势」，增强坚持度与成就感。

### 2.1 目标

- 展示用户全部已打卡训练的动作维度汇总（出现次数 / 总组数 / 总次数 / 容量 / 时长 / 距离等）。
- 提供**时间范围**与**动作**过滤。
- 提供**总体值 + 趣味文案**，提升可读性与趣味性。
- 提供**单动作进阶曲线**（随时间变化）。
- 提供**身体指标折线图**（随时间变化）。

---

## 3. 目标用户

- 所有登录用户（统计只属于本人，复用现有鉴权）。

---

## 4. 数据口径（已确认）

- **纳入范围**：该用户所有 `session_type='workout'` 的训练会话，**排除 `status='cancelled'`**；`in_progress` 与 `completed` 均纳入。
- **「打卡」判定**：一个动作只要**任一执行项存在实际值**（`actual_value_number != null`）即算练过；一个 set 有实际值才算一组。
- **动作维度三个清晰量**：
  - `出现次数`：出现过该动作（有实际数据）的**不同会话数**（作为「频率」排序依据）
  - `总组数`：累计有实际值的组数
  - `总次数`：累计 reps
- **力量动作（set_based）** 另展示：`总容量`（Σ 重量×次数）、`平均重量`、`最大重量`、`平均次数`。
- **有氧动作（single_segment）** 另展示：`总时长`、`总距离`、`平均配速/速度`。
- **总体值**：跨所有动作汇总（训练场数、总容量、总里程、总时长）。
- **身体指标**：`body_metric_logs` 按 `record_date` 排序，同一天多条取最新。
- **趣味等价物**：静态常量（1 头大象≈5000kg、地球周长≈40075km 等），配置于后端常量。

## 5. 功能需求

### 5.1 入口

- **AppShell 导航**新增「统计」入口（`/stats`）。
- **控制台首页**新增「统计」功能入口卡片，卡片内展示**总体值 + 趣味文案**（复用统计 summary 接口的总体数据）。

### 5.2 统计页 `/stats`（从上到下）

1. **汇总 Hero**：总体值 + 趣味文案（1 条总览文案，如「累计训练 N 场 · 总容量 X kg · 总里程 Y km」+ 1 条趣味文案，如「总里程相当于绕地球 X 圈」）。
2. **筛选栏**：
   - 时间范围：近 30 天 / 近 90 天 / 今年 / 全部 + 自定义 from-to。
   - 动作筛选：全部 / 仅力量 / 仅有氧 + 按名称搜索单个动作。
3. **动作统计列表**：卡片按「出现次数」降序，每张：
   - 头部：动作名 + `出现次数 / 总组数 / 总次数` 徽标 + 「查看进阶」展开按钮。
   - 正文：按动作类型显示关键指标（力量→总容量/平均重量/最大重量/平均次数；有氧→总时长/总距离/平均配速）+ 一条趣味文案。
   - 展开：**进阶曲线**（该动作随时间变化的折线）。
4. **身体指标区**：指标切换（体重/体脂/BMI/骨骼肌/腰围等）+ 折线图。

### 5.3 图表类型

- 进阶曲线：LineChart，力量动作默认展示「最大重量」（可切换 最大重量/最大次数/总容量），有氧动作默认「总距离」（可切换 总时长/总距离）。
- 身体指标：LineChart（或 AreaChart）。
- 二期可选：训练频率柱状图（每周/每月打卡次数）。

### 5.4 交互

- 时间范围切换 → 刷新「训练区」汇总与动作列表。
- **身体指标区时间范围独立**于训练区，可独立设置。
- 动作筛选（全部/力量/有氧 + 搜索）→ 过滤动作列表。
- 动作卡片展开/收起进阶曲线。
- 图表 tooltip 显示日期/数值；无数据时给出友好空状态。

---

## 6. 接口契约（摘要）

- `GET /stats/summary?from&to` → 总体值 + 按出现次数降序的动作列表（含各动作聚合指标）。
- `GET /stats/exercise/{exerciseId}?from&to` → 单动作聚合详情 + 进阶序列 `[{date, maxWeightKg?, maxReps?, totalVolume?, totalDurationSeconds?, totalDistanceKm?}]`。
- `GET /stats/body-metrics?metric=weight_kg&from&to` → `[{date, value}]` 身体指标时间序列。

（详细字段见接口文档。）

## 7. 范围

### 本版包含
- 后端：summary / exercise 进阶 / body-metrics 三个只读聚合接口；复用 `MetricKey`、训练会话/指标查询。
- 前端：`/stats` 页（Hero / 筛选 / 动作列表 / 进阶曲线 / 身体指标图）、AppShell 导航、控制台入口卡片、recharts 图表。
- 文档：接口文档、前后端 DDD、changelog。

### 本版不含
- 训练频率柱状图（二期）。
- 导出 / 分享。

---

## 8. 验收标准

1. 统计覆盖所有「已打卡」训练（含未完成周期），排除 cancelled。
2. 动作列表按出现次数降序，三个清晰量（出现次数/总组数/总次数）正确。
3. 力量与有氧动作展示各自正确的指标。
4. 时间范围与动作筛选生效；身体指标时间范围独立。
5. Hero 总体值 + 趣味文案正确展示；控制台入口卡片同样展示。
6. 单动作进阶曲线与身体指标折线图正确渲染（recharts），空数据有友好提示。
7. 后端 `mvn test`、前端 `pnpm test` 通过；契约联调校验通过。
